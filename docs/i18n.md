# Internationalisation (FR / DE / EN)

> Décision : [ADR-0012](adr/0012-i18n-coeur-independant.md). Plan : `docs/specs/PLAN-PLT-02.md`. Terminologie : [i18n-glossaire.md](i18n-glossaire.md).

## À lire avant d'écrire un texte

**Les textes allemands et anglais actuels ont été rédigés par une IA.** Ils conviennent au développement. **Ils doivent être relus par une personne maîtrisant la langue (idéalement du contexte suisse) avant tout usage réel**, en particulier le vocabulaire juridique (*Traktandum*, *Beschluss*, *Protokoll*…).

## Où sont les textes

- `src/messages/fr.json` (source de vérité), `de.json`, `en.json` : la **même structure** dans les trois fichiers.
- Aucune chaîne visible par l'utilisateur en dur dans le code (UI, e-mails, PDF, erreurs). Les **trois langues dans la même PR**.
- Les textes saisis par les utilisateurs (notes, décisions) restent dans leur langue : **aucune traduction automatique** (hypothèse H10).

## Écrire un message

| Règle | Exemple |
|---|---|
| Clé : `domaine.élément` ou `domaine.élément.état`, minuscules, `_` autorisé pour les codes d'erreur | `home.title`, `errors.not_found` |
| Format **ICU MessageFormat** | `{count, plural, =0 {Aucun élément} one {# élément} other {# éléments}}` |
| Jamais de concaténation de morceaux de phrase : une phrase = un message avec ses variables | `Bonjour {name}`, pas `t('hello') + name` |
| Pluriels et genres par `plural` / `select`, pas par `if` dans le code | |
| **Apostrophe typographique `’` (U+2019)** : l'apostrophe droite `'` est un caractère d'échappement ICU (`l'{name}` perd son apostrophe et sa variable) | `L’application`, `n’êtes` |
| **Pas de HTML ni de balises** dans les messages (le contrôle les refuse) | |
| Mêmes variables dans les trois langues | `{name}` partout |
| Un message public d'erreur **ne contient jamais de donnée** (règle de sécurité) | |

## Utiliser un message

```ts
import { createTranslator, localeOfRequest } from '../platform/i18n/index.ts';

const t = createTranslator(localeOfRequest(req)).t;
t('home.title');                         // clé typée : une clé inconnue ne compile pas
t('items', { count: 3 });                // variables ICU
```

- `createTranslator(locale)` ne lève jamais d'exception : message absent ⇒ repli sur le français, puis sur la clé, avec une ligne de journal `i18n.missing_message` (clé et langue seulement).
- **Dates et nombres** : `createFormatters(locale, timeZone?)` (jamais de formatage à la main). Fuseau par défaut `Europe/Zurich`.
- **Langue d'une requête** : `?lang=` explicite > préférence de l'utilisateur > langue de l'organisation > `Accept-Language` > français.

## Conventions suisses

| Sujet | Choix |
|---|---|
| Formats | `fr` → `fr-CH`, `de` → `de-CH`, `en` → `en-GB` (dates jj.mm.aaaa ou jj/mm/aaaa, heure 24 h) |
| Allemand | orthographe suisse **sans « ß »** (`beschliessen`), vouvoiement (« Sie ») |
| Français | vouvoiement, orthographe suisse |
| Séparateurs de nombres | selon les données de locale de Node : les tests vérifient des propriétés stables (séparateur décimal, groupement), pas l'octet exact |

## Contrôles automatiques (bloquants en CI)

- `pnpm i18n:check` (et les tests unitaires, job `unit`) : mêmes clés dans les trois langues, aucun message vide, **mêmes variables** par clé, syntaxe ICU valide, pas d'apostrophe droite, pas de balise, nom de clé conforme. L'échec nomme la **langue**, la **clé** et le **problème** (`de errors.rate_limited missing_key`).
- Chaque `new AppError('code', …)` du code source doit avoir `errors.<code>` dans les trois langues.
- Clés typées : une clé qui n'existe pas dans `fr.json` ne compile pas.
